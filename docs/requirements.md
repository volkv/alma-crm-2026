# Требования задания и их покрытие

Документ — полная проверка продукта по требованиям задания: каждое требование названо своим
идентификатором, а напротив него — где это в продукте, чем проверяется и чего не хватает.
Идентификаторы совпадают с реестром требований, который команда ведёт по тексту задания; нумерация
разделов повторяет разделы задания. Статусы проставлены чтением кода и тестов на текущем коммите и
обновляются с каждым релизом: строка, разошедшаяся с кодом, — дефект этого документа, а не мелочь.
Короткий путь для эксперта — [`README.md`](../README.md): запуск одной командой, демонстрационный
проход и учётные записи занимают пять минут. Эта матрица — для полной проверки по пунктам.

## Легенда статусов

| Статус                       | Что значит                                                                            |
| ---------------------------- | ------------------------------------------------------------------------------------- |
| `реализовано`                | работает в продукте; названы место и проверка                                         |
| `частично`                   | работает не полностью; чего не хватает — в колонке «Ограничения»                      |
| `запланировано (m2\|m3\|m4)` | в продукте пока нет; названы веха и ожидаемое место реализации, без обещаний по датам |
| `не входит`                  | сознательно вне объёма решения, с причиной                                            |
| `не проверено`               | проверка не проводилась (замер, оценка людьми); догадка вместо факта не ставится      |

Вехи: **m4** — заморозка состава и презентация (упаковка документации файлом сделана, `D4`). Строк с вехами **m2**
(ядро процесса, ролей, отчётов и обмена) и **m3** (импорт справочников, замеры отклика и нагрузки,
фирменный стиль, расширение API, уведомления) в матрице не осталось: всё, что стояло за ними,
закрыто кодом. Внутри веха ссылается на место реализации, а не на дату.
