# Данные об обучении

Импорт статистики и показатели, которые из неё считаются. Код —
`src/lib/server/stats/`, схема — `src/lib/server/db/schema/stats.ts`, раздел —
`src/routes/(app)/data/`.

## Снимок вместо текущего значения

Число обучающихся не бывает «просто числом»: оно всегда чьё-то, за какой-то
период и откуда-то взялось. Поэтому единица хранения — **снимок**
(`stat_snapshots`): источник, режим, отчётный период, область покрытия, автор,
момент подтверждения и файл, из которого всё это приехало.

Из этого следуют три правила, на которых держится раздел:

- **В показатели попадает только подтверждённое.** Загруженный, но не принятый
  человеком снимок остаётся черновиком, сколько бы строк в нём ни разобралось.
- **Ничего не удаляется и не перезаписывается.** Замещение — это признак на
  снимке, исправление — новая версия строки. На вопрос «почему здесь такое
  число» всегда есть ответ, и ответ этот — конкретная загрузка.
- **Ноль и отсутствие данных — разные вещи.** «Ноль заявок» это результат,
  «нет данных» — незаполненная колонка. Различие держится от разбора файла
  (`parseCount`) до представления показателей (`sum` пропускает `NULL`) и до
  экрана (прочерк вместо нуля).

## Таблицы

| Что                       | Зачем                                                                      |
| ------------------------- | -------------------------------------------------------------------------- |
| `stat_snapshots`          | Загрузка целиком: источник, режим, период, область, состояние, счётчики    |
| `stat_rows`               | Строки файла после разбора: ссылки на справочник, числа, претензии, версия |
| `stat_program_indicators` | Представление: показатели по программе × организации × периоду             |

Состояния снимка (`status`): `uploading` — файл принят, `mapped` — колонки
сопоставлены и строки разобраны, `validated` — счётчики пересчитаны,
`confirmed` — принят в показатели, `rejected` — отклонён с объяснением.
Отклонённый снимок остаётся в системе вместе со строками: по нему видно, что
именно не приняли.

Актуальность живёт в двух признаках:

- `stat_snapshots.is_current` — снимок подтверждён и ещё не замещён;
- `stat_rows.replaced_by_row_id` — строку заменило исправление.

Оба ставит подтверждение, и оба проверяет представление. Инварианты держит
база: `is_current` бывает только у подтверждённого, у подтверждённого всегда
заполнен `confirmed_at`, у верной строки всегда есть организация и программа,
конец периода не раньше начала.

## Режимы

| Режим        | Что делает подтверждение                                                                                                           |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| `full`       | Снимает `is_current` с прежней выгрузки того же **источника, периода и области** и ссылается на неё через `supersedes_snapshot_id` |
| `append`     | Ничего не вытесняет: снимок просто становится ещё одним текущим                                                                    |
| `correction` | У строки с тем же ключом проставляется `replaced_by_row_id`, новая строка получает версию `+1`                                     |

Область покрытия (`coverage`) — это `{organizationIds, siteIds, programIds}`.
Пустая область означает «всё, что есть в файле», и тогда замещение считается по
источнику и периоду. Массивы нормализуются при записи (сортировка, без
повторов): «та же область» не должна зависеть от порядка идентификаторов в
файле.

Строка исправления, которой нечего заменять, просто добавляется — это видно по
её версии, она остаётся первой.

## Сопоставление колонок

`suggestMapping(headers)` (`stats/mapping.ts`) предлагает, какая колонка файла
чем является; применяет предложение человек. Правила:

- название колонки приводится к сравнимому виду: регистр, «ё», знаки
  препинания и лишние пробелы не значимы («Охват, план» = «охват план»);
- точное совпадение со словарём сильнее вхождения, длинный синоним — сильнее
  короткого;
- одно поле достаётся одной колонке: рядом стоят «Охват, план» и «Охват,
  факт», и без этого правила предложение зависело бы от порядка колонок.

| Поле              | Синонимы (начало списка)                                          |
| ----------------- | ----------------------------------------------------------------- |
| `organization`    | организация, вуз, университет, учебное заведение, ИНН, university |
| `site`            | площадка, филиал, кампус, подразделение, campus                   |
| `program`         | программа, код программы, направление подготовки, program         |
| `periodStart`     | начало периода, дата начала, период с, start date                 |
| `periodEnd`       | конец периода, дата окончания, период по, end date                |
| `applications`    | заявки, подано заявок, количество заявок, applications            |
| `enrolled`        | зачислено, обучающихся, студентов, слушателей, enrolled           |
| `parallelStreams` | потоки, параллельные потоки, групп, streams                       |
| `completed`       | завершили обучение, окончили, выпущено, completed                 |
| `coveragePlan`    | охват план, плановый охват, план, coverage plan                   |
| `coverageFact`    | охват факт, фактический охват, факт, coverage fact                |

Полный словарь — в `SYNONYMS` (`stats/mapping.ts`). Однобуквенных и слишком
общих слов в нём нет намеренно: подстрока «с» нашлась бы в каждом заголовке.

`organization` принимает и название, и ИНН: различить их можно по самому
значению (десять или двенадцать цифр), и второе поле ради этого не нужно.

**Подсказка — это шов.** `stats/advisor.ts` объявляет интерфейс
`MappingAdvisor`; в поставке одна реализация — `kind: 'mock'`, правила по
словарю. Второго поставщика (модели) нет намеренно: основной процесс обязан
работать без сети, а подсказка, без которой импорт не идёт, — уже не подсказка.

## Разбор строки

`buildRows` (`stats/build.ts`) — чистая функция: таблица, сопоставление и
справочник на входе, строки с претензиями на выходе. Что становится претензией:

- организация или программа не найдена в справочнике, либо под значение
  подходит несколько записей — выбирать наугад нельзя;
- значение в числовом поле не разбирается в целое число или отрицательно;
- дата не разбирается или период строки перевёрнут;
- в строке больше значений, чем колонок в шапке (сдвиг разделителей);
- **дубль**: та же организация, программа и период, что у другой строки файла.
  Претензию получают **обе** строки: сложить их — значит придумать данные,
  выбрать одну — значит выбрать наугад.

Строка с любой претензией не попадает в показатели, но остаётся в снимке. Если
колонок периода в файле нет, строка берёт период снимка.

Исходный файл лежит в хранилище документов неизменяемым (вид — «Отчёт») и
виден в разделе «Документы»: по нему всегда можно проверить, из чего получились
показатели.

## Форматы файла

Импорт читает книги **XLS** и **XLSX**, текстовые таблицы **CSV** и **JSON**.
Формат определяется по содержимому файла — по подписи первых байт, — а не по
расширению и не по типу, который назвал браузер: `.xls` в имени бывает у чего
угодно, включая XLSX и HTML-таблицу, сохранённую так из 1С.

Таблицы читает общий модуль `spreadsheet/read.ts` (SheetJS) — тот же, что пишет
выгрузки: кодировка (UTF-8 с меткой порядка байтов и без неё, UTF-16,
windows-1251), разделитель (`;`, `,`, табуляция, считается только вне кавычек),
кавычки и переводы строк внутри значений — его работа. Данные берутся с первого
листа книги; если листов больше, мастер говорит об этом предупреждением.

**Значение в текстовом файле берётся так, как оно написано.** Для книги истина
— это значение ячейки (дата лежит датой, число числом), а для CSV значение
всегда догадка разборщика, и догадка бывает неверной: «12,5» он читает как 125,
приняв запятую за разделитель разрядов, а ИНН «0278000000» — как число без
ведущего нуля. Поэтому у текстового файла разбор берёт исходный текст ячейки, а
числом и датой его делает уже разбор строки (`parseCount`, `parseCalendarDate`):
разряды, разделённые пробелом (в том числе неразрывным), — число, а «12,5» в
поле показателя — претензия, а не 125.

### JSON

Две формы, обе — список записей:

```json
[{ "Вуз": "СЗПУ", "Подано заявок": 120 }]
{ "source": "LMS", "rows": [{ "Вуз": "СЗПУ", "Подано заявок": 120 }] }
```

Во второй форме список ищется по ключу `rows`, `items` или `data` — так его
называют системы, которые такие выгрузки отдают. Если списков в файле сразу
несколько, это отказ: не тот список — это молча не те числа в отчёте, и
выбирать наугад нельзя.

Колонки — это ключи записи. Вложенный объект разворачивается через точку
(`org.inn`), массив — через индекс (`tags.0`): колонка обязана быть адресуемой
именем. Шапка собирается по всем записям в порядке первой встречи ключа, и
**разный набор ключей — предупреждение, а не отказ**: выгрузка, где у части
записей нет необязательного поля, — обычное дело, недостающее значение остаётся
пустым. `null` и пустой объект — это пустое значение, а не слово «null».

Границы названы числом, и отказ говорит это число: не больше
`MAX_STAT_FILE_ROWS` строк, `MAX_STAT_FILE_COLUMNS` колонок и
`MAX_STAT_JSON_DEPTH` уровней вложенности (`contracts/stats.ts`), файл — не
больше 25 МиБ, как любой документ.

Кодировка текста определяется по содержимому и в мастере, и на входе в
хранилище документов: проверка типа файла (`documents/mime.ts`) читает текст
тем же кодом, что и разбор таблиц (`spreadsheet/encoding.ts`), поэтому CSV из
русского Excel — в windows-1251 — принимается как есть. Признание текстом идёт
последним: сначала проверяются подписи двоичных форматов, и переименованная
разметка текстом не считается ни в одной кодировке.

### Происхождение строки

У каждой строки разбора записано, откуда она взялась: номер строки листа (с
единицы, шапка — тоже строка) или индекс элемента массива JSON (с нуля — так
его адресует любой инструмент, которым файл откроют). Претензия, по которой
строку ищут в файле руками, называет это место прямо: «строка 7 файла: 1
значение сверх колонок шапки». Номер строки в снимке (`stat_rows.row_no`) — это
её порядок среди строк данных: пустые строки и шапка в него не считаются, и на
экране проверки нумерация идёт подряд.

### Что мастер показывает о файле

На шаге сопоставления под таблицей стоит строка «Файл „вузы-2026.csv“ прочитан
как текстовая таблица, кодировка windows-1251, разделитель — точка с запятой,
лист „Sheet1“». Это ответ на вопрос «почему колонки не те»: съехавшие колонки
объясняет разделитель, потерянные строки — прочитанный лист, а кракозябры —
кодировка. Рядом — предупреждения о файле: лишние листы книги и колонки, которые
есть не у всех записей JSON.

## Показатели и рейтинг

`stat_program_indicators` складывает строки подтверждённых **текущих** снимков,
верные и не заменённые исправлением, по ключу «программа × организация ×
период». Периоды между собой не складываются: период входит в ключ
группировки, а пересекающиеся периоды посчитали бы одних и тех же обучающихся
дважды.

Рейтинг (`rankPrograms`) — **гипотеза до технического задания**:

```
score = 1 × заявки + 2 × зачислено + 5 × параллельные потоки
```

Веса объявлены в `RANKING_WEIGHTS` (`$lib/contracts/stats`) рядом с
`explainScore`, который раскладывает балл на слагаемые. Сумма вкладов равна
баллу — это проверяется тестом, потому что объяснение, не сходящееся с числом,
хуже отсутствия объяснения. Смысл весов: заявка — это спрос, зачисление —
подтверждённый спрос, параллельный поток — спрос, который уже потребовал от
вуза отдельного расписания. Точные веса и сам набор слагаемых определяются по
датасету заказчика.

Рейтинг считается только по выбранному периоду; без выбора вкладка так и
говорит, а не складывает всё подряд.

## Права и журнал

| Право          | Что открывает                                            |
| -------------- | -------------------------------------------------------- |
| `stats.read`   | Раздел, карточку снимка, показатели и рейтинг            |
| `stats.import` | Загрузку, сопоставление, проверку, подтверждение и отказ |

`viewer` получает только `stats.read`, `manager` и `admin` — оба. События
журнала: `stats.snapshot_created`, `stats.snapshot_mapped`,
`stats.snapshot_confirmed`, `stats.snapshot_rejected`. Попытка загрузить данные
без права пишется с исходом `denied` — администратор должен узнать о ней, а не
только получить 403 в ответе. У проверки (`validateSnapshot`) своего события
нет: она ничего не решает, а пересчитывает счётчики по уже записанным строкам.

Область доступа применяется к показателям и рейтингу (у строки ровно одна
организация) и не применяется к самим снимкам: одна загрузка описывает сразу
десятки вузов, и показать её частично значило бы показать неверные счётчики.

## Интерфейс

- `/data` — список снимков: источник, режим, период, область, состояние,
  строки и ошибки, кто и когда загрузил. Фильтры и поиск живут в адресе.
- `/data/new` → `/data/<id>/mapping` → `/data/<id>/check` — мастер из трёх
  шагов, каждый на своей странице: у шага есть адрес, и к сопоставлению можно
  вернуться из списка через неделю.
- `/data/<id>` — карточка снимка: чем он был, что в нём разобралось, кого
  замещает, ссылка на исходный файл.
- `/data/indicators` — показатели по программам и организациям и вкладка
  «Рейтинг программ» с колонкой «почему».
- `/data/dashboard` — портфель данных за один отчётный период.

Три взгляда на одни и те же данные — снимки, показатели и дашборд —
переключаются вкладками (`components/stats/section-tabs.svelte`). Это ссылки, а
не состояние экрана, и выбранный период переезжает вместе с переходом.

## Дашборд и экспорт

`/data/dashboard` отвечает на вопрос «что у нас за этот год»: сколько программ и
вузов, сколько заявок и обучающихся, кто впереди по рейтингу и из каких загрузок
всё это сложилось. Собирает картину один сервис (`stats/dashboard.ts`) — плитки,
разбивка, распределение, рейтинг и происхождение обязаны сходиться между собой,
а собранные по отдельности они сойтись не обязаны.

**Период всегда один и всегда в адресе.** Обращение без периода уводит на
последний, по которому есть подтверждённые данные. Складывать периоды нельзя —
это то же правило, что и у показателей: пересекающиеся периоды посчитали бы
одних и тех же обучающихся дважды. Поэтому у селектора периодов нет пункта
«все», в отличие от фильтров списка.

Что на экране:

| Блок                   | Что показывает                                                                         |
| ---------------------- | -------------------------------------------------------------------------------------- |
| Плитки                 | программы, вузы и площадки, заявки, обучающиеся, потоки, охват факт к плану (в %)      |
| Топ программ           | верхушка того же рейтинга с разложением балла; по клику — показатели этой программы    |
| Программы по уровню    | школьные отдельно от вузовских, рядом СПО и ДПО                                        |
| Распределение по вузам | строка на организацию с сортировкой в адресе и ссылкой в справочник                    |
| Происхождение          | снимки, из которых сложился период: источник, режим, файл, автор, момент подтверждения |

Плитки строит `statDashboardTiles` — чистая функция в контрактах, общая для
экрана и для листа «Сводка» в выгрузке: два набора чисел под одним названием
однажды разошлись бы. Ноль показывается нулём, отсутствие данных — прочерком с
подписью «нет данных»; доля охвата от нулевого плана не считается вовсе, потому
что она не определена, а не равна нулю.

Школьные программы отличаются от вузовских по `programs.level` (`school` против
`bachelor`/`master`/`specialist`); группы и их названия объявлены в контрактах
(`STAT_PROGRAM_GROUPS`), а не в SQL, чтобы правило было одно.

**Площадки.** Представление показателей сведено к «программа × организация ×
период», площадки в нём нет. Поэтому распределение строится по организациям, а
число площадок берётся из строк тех же снимков — единственный запрос дашборда,
который повторяет условия представления, и повторяет он их ради происхождения, а
не ради чисел.

### Кэш

Собранный дашборд лежит в Redis минуту (`STATS_DASHBOARD_TTL_SECONDS`). Ключ —
`lct:stats:dashboard:<поколение>:<область доступа>:<период>`:

- **период** в ключе, потому что дашборд всегда про один период;
- **область доступа** — потому что куратор трёх вузов не должен получить
  картину, собранную администратором;
- **поколение** — счётчик, который увеличивает подтверждение снимка
  (`invalidateStatsDashboard` в `confirmSnapshot`). Ключи прежнего поколения
  никто больше не прочитает, и удалять их не нужно: они уходят по сроку жизни.
  Перебирать ключи сканированием ради инвалидации не приходится.

Подтверждение — единственное действие, которое меняет показатели, поэтому
других точек инвалидации нет. Отклонение снимка картину не меняет: отклонённый
снимок никогда не был текущим.

### Отчёт в XLSX

Кнопка «Выгрузить отчёт (xlsx)» есть на дашборде и на показателях (там она
выключена, пока не выбран период). Отдаёт файл `/data/export?period=…`, собирает
`stats/export.ts` из того же представления дашборда — отчёт, который считает
сам, разойдётся с экраном, с которого его выгрузили.

Листы: «Сводка» (плитки и разбивка по уровням), «Программы» (рейтинг со
слагаемыми и вкладом каждого), «Вузы и площадки», «Источники» (снимки периода).

Правила ячеек:

- **числа приезжают числами.** Строка «1 234» не суммируется и не сортируется,
  но выглядит в ячейке как число;
- **пустая ячейка — это «нет данных»,** а ноль — записанный в выгрузке ноль; на
  листе «Сводка» это сказано словами;
- **текст обезвреживается.** Значение, начинающееся с `=`, `+`, `-`, `@`,
  табуляции или возврата каретки, таблица читает как формулу — и название вуза
  из чужой выгрузки выполнится у того, кто открыл файл. Впереди ставится
  апостроф, которым таблицы помечают «это текст». Правило и список символов те
  же, что у выгрузки журнала в CSV (`audit/index.ts`), но константа своя:
  из журнала она не экспортируется.

Имя файла — «Данные об обучении `<начало>` — `<конец>` на `<день>`.xlsx», где
день считается по Москве (`formatIsoDay`), как и все календарные сутки в
продукте: по UTC файл, снятый вечером, назывался бы вчерашним числом.

Право на выгрузку — то же `stats.read`, что и на раздел: отчёт показывает ровно
те числа, которые уже на экране. Сама выгрузка пишется в журнал событием
`stats.exported`. Период в подробностях события не лежит: `validateAuditDetails`
принимает только ссылки вида `<что-то>Id` и закрытый служебный список, а записи,
на которую можно сослаться, у отчётного периода нет, — что именно выгрузили,
видно по времени события и по тому, какие снимки были подтверждены на тот момент.

### Кто видит исходный файл

Файл выгрузки, из которого сложился снимок, лежит в `documents` **вне
взаимодействия** (`interaction_id` пуст, вид — `report`), поэтому он виден и в
разделе документов: кладёт его туда право `stats.import`, а скачивает —
`documents.read`. Область доступа
к документам без взаимодействия не применяется (`assertDocumentAccessible`), и
отдельного права на файлы статистики нет: любой, кто читает документы, скачает
исходную выгрузку по ссылке «Скачать файл» на карточке снимка. Скачивание
пишется в журнал событием `documents.downloaded`.

Маскирование контактов на файл не распространяется — оно живёт в сериализаторе
людей и работает со строками справочника, а не с содержимым загруженного файла.
Если в выгрузку попали персональные данные, `people.read_pii` их не спрячет:
файл отдаётся как есть. Пока это ограничение, а не решение; разделить «читать
показатели» и «скачать исходник» может только отдельное право на файлы снимка.

## Что переделается по техническому заданию

Набор полей — гипотеза, и переименование после уточнения требований ожидаемо.
Под вопросом:

- **состав показателей**: `applications`, `enrolled`, `parallelStreams`,
  `completed`, `coveragePlan`, `coverageFact` — то, что названо в постановке
  задачи; в датасете заказчика их набор и смысл могут отличаться (например,
  «охват» может оказаться долей, а не числом людей);
- **зерно строки**: сейчас это «организация × площадка × программа × период».
  Возможно, понадобится курс, форма обучения, компания-заказчик или
  мероприятие;
- **виды периода**: `academic` и `calendar`; в отчётности заказчика может
  появиться семестр или квартал;
- **источники**: `file`, `lms`, `site`, `manual` — гипотеза о том, откуда
  приходят данные; список адаптеров уточняется вместе с интеграциями;
- **веса рейтинга** и сам вид формулы — считаются по датасету;
- **область покрытия**: сейчас это списки идентификаторов; возможно,
  понадобится выражение вида «все вузы региона».
