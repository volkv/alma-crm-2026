# Снимки и ролики README

Всё, что README показывает картинками, лежит в `docs/media/` и собирается скриптами из
`scripts/readme-media/`. Руками ничего не снимают: снимок, сделанный мышкой, устаревает молча —
экран переименовали, а картинка осталась прежней, и заметить это можно только случайно. Скрипт же
пересобирает любой кадр одной командой, и расхождение с продуктом видно сразу.

| Файл                                   | Что внутри                                                          |
| -------------------------------------- | ------------------------------------------------------------------- |
| `scripts/readme-media/shots.ts`        | список кадров: имя файла, адрес, роль, что ждать перед съёмкой      |
| `scripts/readme-media/capture.ts`      | съёмка кадров                                                       |
| `scripts/readme-media/record.ts`       | запись роликов и сборка GIF через `ffmpeg`                          |
| `docs/media/*.svg`, `docs/media/*.jpg` | баннер, кнопки и логотип команды — рисованные, скриптами не берутся |

## Что нужно

- поднятый стенд, в который можно войти;
- `SEED_DEMO_PASSWORD` — пароль демонстрационных записей **каталога учётных записей**; в репозитории
  его нет, он принадлежит той машине, на которой подняли Keycloak;
- для роликов — `ffmpeg` в `PATH`.

Съёмка ходит по стенду тем же путём, что и человек: нажимает «Войти», заполняет форму Keycloak,
возвращается в приложение. Другого входа в системе нет, и подделанная сессия снимала бы систему,
которой не существует.

## Как снять

```bash
docker compose up -d --build            # стенд целиком
export SEED_DEMO_PASSWORD='…'           # пароль демонстрационных записей каталога
export MEDIA_BASE_URL=http://localhost:3000

node scripts/readme-media/capture.ts --list        # что вообще снимается
node scripts/readme-media/capture.ts               # все кадры
node scripts/readme-media/capture.ts reports exchange   # только названные
node scripts/readme-media/record.ts                # все ролики
```

Кадр сохраняется в `docs/media/<имя>.png`, ролик — в `docs/media/<имя>.gif`. Имя кадра и есть имя
файла, на который ссылается README: добавили строку в `shots.ts` — добавили картинку.

Неснятый кадр не останавливает съёмку: скрипт печатает список несобранного и завершается ненулевым
кодом. Это не перестраховка — кадр обычно не снимается не потому, что сломан скрипт, а потому что
сломан экран: страница не ожила или на ней нет того, ради чего её открывали.

## Стенд для съёмки

Данные на кадрах — набор демонстрационного стенда (`scripts/seed`), и он детерминирован: адрес
карточки на любой машине получается один и тот же, поэтому `shots.ts` берёт идентификаторы у
`scripts/seed/ids.ts`, а не переписывает их числом.

Чтобы на кадре `exchange` был не пустой журнал, обмен на стенде должен что-то пережить. Порядок:

1. ключи обмена на стенде уже есть: их заводит сид по `EXCHANGE_API_KEY_CMS` и
   `EXCHANGE_API_KEY_LMS` из `.env` (`docs/seeds.md`, «Ключи обмена»), и теми же значениями
   представляются имитаторы. Выпускать ключ в интерфейсе и перезапускать `mock-cms`/`mock-lms` не
   нужно;
2. переменных в `.env` нет — задать их (по ключу на подключение, разные значения) и поднять стенд
   заново: `docker compose up -d`. Ключ заводится сидом при старте приложения, имитаторы получают
   его тем же `up`;
3. нажать триггер заявки: `curl -X POST http://localhost:58081/__send-application -H 'content-type: application/json' -d '{"form":"b2b"}'`;
4. дождаться, пока снимок статуса уедет обратно (`curl http://localhost:58081/__state`);
5. на карточке заведённого взаимодействия нажать «Отправить в LMS»;
6. вернуть результат потока: `POST /api/v1/exchange/learning-groups/results` ключом системы
   обучения (`EXCHANGE_API_KEY_LMS`; ключ сайта там получит `403`), тело — пример из
   `docs/exchange-contract.md`, раздел 6.
