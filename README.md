# LCT CRM

CRM для оператора образовательных программ: учёт вузов, компаний-заказчиков и взаимодействий с ними.

## Требования

- Docker 25+ с плагином Compose
- Node.js 24 (версия зафиксирована в `.nvmrc`)
- pnpm 10 (`corepack enable`)

## Запуск одной командой

```bash
docker compose up --build
```

Поднимаются приложение, PostgreSQL 17, Redis 8, Gotenberg и Mailpit; миграции применяются
автоматически перед стартом приложения. Дальше:

- приложение — http://localhost:3000
- почтовый ящик Mailpit — http://localhost:8025

Остановить и удалить данные: `docker compose down -v`.

## Демо-учётки

Со стендовой конфигурацией (`DEMO_MODE=true`) контейнер после миграций заполняет базу
демонстрационными данными: справочник учебных заведений и компаний, контакты, программы,
продукты и три учётные записи.

| Почта                        | Имя                | Роль          |
| ---------------------------- | ------------------ | ------------- |
| `admin@demo.lct-crm.local`   | Администратор Демо | Администратор |
| `manager@demo.lct-crm.local` | Менеджер Демо      | Менеджер      |
| `viewer@demo.lct-crm.local`  | Наблюдатель Демо   | Наблюдатель   |

На странице входа для них появляются кнопки «Войти как …» — пароль не нужен. Обычной формой
они входят с паролем из `SEED_DEMO_PASSWORD` (значение для локальной работы — в `.env.example`).

Локально те же данные заливает `pnpm run db:seed`; подробности — в [`docs/seeds.md`](docs/seeds.md).

## Демо-проход

Пять минут, чтобы увидеть весь процесс: от просроченного взаимодействия до
подписанного соглашения.

1. Откройте http://localhost:3000 и нажмите «Войти как менеджер».
2. Перейдите в «Взаимодействия» и включите фильтр «Просроченные» — таких
   четыре. Откройте «СЗПУ: подготовка по прикладной информатике, 2026/2027»:
   оно стоит на первой стадии дольше норматива.
3. В карточке видно, что происходит, что мешает и кто должен действовать.
   Кнопка перехода на следующую стадию недоступна и объясняет почему: не закрыты
   обязательные пункты чек-листа.
4. Закройте оба пункта на вкладке «Стадия» — кнопка «Перейти: Коммуникация и
   сверка программ» оживает. Нажмите её: лента стадий и история обновятся.
5. На вкладке «Документы» заполните поля соглашения и нажмите «Сгенерировать
   соглашение» — оно соберётся сразу в DOCX и PDF. Скачайте PDF.
6. Войдите администратором и откройте «Журнал действий»: переход по стадии и
   сборка документа уже там, с автором и временем.

Тот же сценарий проходит автоматически — `e2e/demo-pass.test.ts`.

## Разработка

```bash
cp .env.example .env                                        # значения уже совпадают с compose
docker compose up -d postgres redis gotenberg mailpit       # только инфраструктура
pnpm install
pnpm run db:migrate
pnpm dev                                                    # http://localhost:5173
```

Все переменные окружения обязательны: без любой из них сервер не стартует и пишет,
чего именно не хватает. Список — в `.env.example`.

## Проверки

```bash
pnpm run check:all
```

Это lint → проверка типов → модульные тесты → интеграционные тесты → сборка → e2e.
Интеграционные и e2e-тесты требуют запущенного Docker.

Подробности — в [`docs/development.md`](docs/development.md).

## Деплой

Развёртывание на сервере — отдельный оверрайд `docker-compose.prod.yml` (приложение слушает
только loopback, лимиты памяти, конфигурация из `.env`) и шаблон vhost
`deploy/nginx/crm.conf.example`. Пошагово — в [`docs/deployment.md`](docs/deployment.md).
