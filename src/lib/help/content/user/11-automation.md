Карта ниже отвечает на один вопрос: что на каждом шаге работы с вузом система
берёт на себя. Шаги — это стадии базового процесса «Работа с ВУЗ», в том же
порядке и с теми же названиями, что на доске. Карта живая: ссылки и числа на
ней — под ваши права.

<!-- automation-map -->

## Три вида

- **Делает система** — результат появляется сам, без ручного ввода: пакет
  документов, статус «передан» по акту, подтверждение стадии итогом из LMS.
- **Помогает сотруднику** — система готовит данные, решение и ввод остаются за
  человеком: кандидаты в контакты с сайта вуза, рейтинг программ, редакции
  документов.
- **Контролирует** — без доказательства дальше не пройти или система сама
  поднимает тревогу: обязательные пункты чек-листа, отметка «Утверждён» на
  подписании, эскалация зависшей стадии.

Пункт с меткой **«В работе»** описывает то, что ещё не выпущено. Он стоит на
карте, чтобы было видно, где шаг пока держится на человеке.

## Что в строке

У каждого шага — от одного до трёх пунктов. В пункте:

- что делает система — одной фразой;
- как проверить — что увидеть на экране, чтобы убедиться;
- **«Где это»** — ссылка на экран. Если экран закрыт вашей роли, он назван
  без ссылки;
- ссылка на статью справки об этом экране;
- число из журнала обмена — там, где оно есть: сколько заявок с сайта принято,
  сколько заявок на учебные группы ушло в LMS, сколько результатов групп
  принято. Числа видит тот, кто ведёт обмен (право «Настройка вебхуков и
  интеграций»), и это итог по всему журналу, а не по вашей области.

## Коротко по шагам

| Шаг                                        | Что делает система                                                                                                           |
| ------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| 1. Поиск контактных лиц                    | Паспорт организации: реквизиты из ЕГРЮЛ; руководители подразделений с сайта вуза — в контакты одним щелчком на карточке вуза |
| 2. Коммуникация и сверка программ          | Подбор программ школы под программы вуза по кодам ФГОС на карточке вуза; рейтинг программ — что предлагать                   |
| 3. Встреча с представителями               | Приглашение `.ics` с повесткой из чек-листа прямо из карточки; чек-лист держит переход                                       |
| 4. Обмен пакетом документов                | Пакет документов одной кнопкой из шаблонов процесса                                                                          |
| 5. Корректировка документов                | Редакции документа с историей                                                                                                |
| 6. Подписание соглашения                   | Стадию подтверждает только документ с отметкой «Утверждён»                                                                   |
| 7. Передача материалов и лицензий          | Акт передачи переводит позиции в «передан»; контроль сроков лицензий и «Запустить продление»                                 |
| 8. Сопровождение внедрения                 | Заявка на учебную группу уходит в LMS из карточки                                                                            |
| 9. Обучение преподавателей                 | Группа «Обучение преподавателей» в LMS, результаты на карточке                                                               |
| 10. Актуализация образовательной программы | Новая версия программы, прежние сохраняются                                                                                  |
| 11. Ведение занятий                        | Итог нужной группы из LMS подтверждает стадию; снимок статистики из результатов                                              |
| 12. Актуализация документации              | Обновлённые материалы — новой редакцией документа                                                                            |
| 13. Повышение квалификации                 | Группа «Повышение квалификации» в LMS, результаты на карточке                                                                |
| 14. Контроль исполнения                    | Эскалация зависших стадий руководителю; отчёт на дату; утренняя сводка «Мой день» письмом                                    |

На всём процессе работают заявки с сайта (создают или обновляют взаимодействие и
возвращают статус на сайт), лента событий на «Сводке» и в карточке, чек-лист и
срок у каждой стадии.
