Раздел [«Пользователи»](/settings/users) открывается по праву «Управление
пользователями и ролями».

## Записи заводит вход, а не администратор

Кнопки «создать пользователя» здесь нет и быть не может. Учётная запись
появляется сама при первом входе человека через каталог. Имя, почта и роль
приводятся к тому, что написано в токене, при **каждом** входе: источник истины о
человеке — каталог, а не наша база.

Соответствие ролей: `crm-admin` → администратор, `crm-lead` → руководитель,
`crm-user` → менеджер. Если ролей несколько, берётся старшая. Незнакомая роль
каталога игнорируется.

Первый вход связывает человека с записью так:

1. запись с этим субъектом уже есть — входит она;
2. субъект неизвестен, но подтверждённая почта из токена числится за
   существующей записью — записи проставляется субъект, и человек входит со
   своим прежним портфелем;
3. не нашлось ни того, ни другого — заводится новая запись.

Неподтверждённая почта в связывании не участвует.

## Что меняется здесь

- **Руководитель** — выпадающий список в строке, сохраняется сразу. На нём
  держится область доступа руководителя и адрес эскалации.
- **Выключить / Включить.** Учётные записи не удаляются: на них ссылается журнал,
  взаимодействия и ключи. Свою запись выключить нельзя.
- **«Отвязать»** — стирает связь записи с субъектом каталога.

Роль и имя здесь не правятся: их перепишет ближайший вход.

## Когда нужна «Отвязать»

Кнопка нужна ровно в одном случае: **каталог перезавели**. Учётная запись в
каталоге создана заново, у того же человека появился другой субъект, и вход его
не узнаёт — он либо заводит двойника, либо упирается в занятую почту.

«Отвязать» стирает субъект у нашей записи. Следующий вход свяжет её заново по
подтверждённой почте, и человек войдёт со своим прежним портфелем: вузами,
взаимодействиями, ключами и следом в журнале. Сессии владельца при этом гасятся.

## Состояния в списке

| Бейдж           | Что значит                                                    |
| --------------- | ------------------------------------------------------------- |
| Работает        | запись активна                                                |
| Выключен        | вход закрыт, данные и история остались                        |
| Демо            | демонстрационная запись стенда                                |
| Внешняя система | машинный субъект обмена; войти им нельзя ни при каких токенах |
| Не связан       | запись ни разу не входила через каталог                       |

Колонка «Последний вход» показывает «ни разу», если входа не было.
