Система не показывает «что-то пошло не так» и не прячет причину. У любого отказа
есть три вещи: **код ответа**, **фраза по-русски** и **код обращения** — по
последнему случай находится в логе сервера одной строкой.

![Страница отказа: код ответа, фраза сервера и код обращения](/help/admin/errors-1.png)

## Код обращения

Код обращения (`requestId`) — это идентификатор **одного запроса**. Он выдаётся
каждому запросу, уходит в лог сервера, в тело ответа API и в заголовок ответа
`x-request-id`; на странице отказа он написан внизу.

Его и просят прислать. По коду обращения администратор находит в логе именно ту
попытку, а не похожую: «вчера не открывалась карточка» ищется часами, код
обращения — секунды. Пользователю достаточно скопировать строку с экрана.

Код обращения **не секрет** и ничего не раскрывает: это случайный UUID, который
живёт ровно один запрос.

## Отказы на экране

| Код   | Что случилось                                                | Что делать                                                                  |
| ----- | ------------------------------------------------------------ | --------------------------------------------------------------------------- |
| `400` | данные не прошли проверку                                    | исправить то, что названо во фразе; в форме претензия стоит рядом с полем   |
| `403` | у учётной записи нет права на это действие                   | проверить роль в разделе «Пользователи»; на демонстрации — см. ниже         |
| `404` | записи нет — **или** она вне области доступа                 | проверить ссылку; если запись чужая, попросить назначить вас ответственным  |
| `409` | действие спорит с текущим состоянием записи: её уже изменили | обновить страницу и повторить, глядя на новое состояние                     |
| `413` | файл или запрос больше, чем принимает сервер (до 25 МиБ)     | ужать файл или разбить на части                                             |
| `415` | запрос пришёл не в том формате, в каком его отправляет форма | повторить со страницы системы, а не из стороннего инструмента               |
| `500` | сбой на нашей стороне                                        | прислать код обращения; в логе сервера по нему лежит полная запись с местом |

**`404` вместо `403` — так задумано.** Запись вне области доступа отвечает «не
найдено», а не «запрещено». Иначе перебором идентификаторов было бы видно, какие
вузы и дела существуют за границей области, — а это и есть та граница, ради
которой область заведена.

**Отказ по правам записывается в журнал действий.** Попытка сделать то, на что
права нет, попадает в [«Журнал»](/audit) с исходом «Отказ»: пользователь
видит фразу, администратор — строку.

**«Запрос отправлен с другого сайта и отклонён»** — это тоже `403`, но по другой
причине: форма пришла со страницы, которая приложению не принадлежит. Так
выглядит подделанный запрос; так же выглядит и попытка отправить форму из
стороннего инструмента. Лечится одинаково — открыть форму в системе и повторить.

**Слишком частые попытки входа** отдельной страницы отказа не дают: страница
входа сама говорит словами, сколько ждать. Ограничение считается по адресу
обратившегося и защищает каталог учётных записей от перебора.

**На демонстрационном стенде** часть действий закрыта правами, а не спрятанными
кнопками: управление пользователями, выпуск ключей доступа, внешние адреса и
секреты подключений, обезличивание. Отказ по ним — не сбой стенда; подробности —
в статье [«Права и граница демонстрации»](/help/admin/access).

## Отказы публичного API

Ответ на любой неуспешный запрос к `/api/v1` — один и тот же конверт, без стека
и без текста запроса к базе:

```json
{
	"error": {
		"code": "validation",
		"message": "Запрос не прошёл проверку",
		"requestId": "0f0d1f0a-7c9a-4a0b-9f2e-1b7c3d4e5f60",
		"details": { "issues": ["query.page: Номер страницы — целое число"] }
	}
}
```

| Код                    | HTTP  | Когда                                                                         |
| ---------------------- | ----- | ----------------------------------------------------------------------------- |
| `validation`           | `400` | параметры или тело не прошли проверку; разбор по полям — в `details.issues`   |
| `unauthorized`         | `401` | ключа нет, он недействителен, отозван или его владелец выключен               |
| `forbidden`            | `403` | владельцу ключа не хватает права — или это ключ обмена вне маршрутов обмена   |
| `not_found`            | `404` | записи нет — или она вне области доступа владельца ключа                      |
| `conflict`             | `409` | действие спорит с состоянием записи                                           |
| `idempotency_mismatch` | `422` | заголовок `Idempotency-Key` уже использован, но с другим телом запроса        |
| `rate_limited`         | `429` | превышен лимит частоты: 600 запросов в минуту с адреса, 120 в минуту по ключу |
| `internal`             | `500` | сбой на нашей стороне; это тот случай, когда `requestId` нужно прислать       |

Первые пять кодов — те же, что и на экране: правило одно, а транспорт разный.
Остальные три существуют только у API — у страницы нет ни ключа доступа, ни
заголовка идемпотентности.

Полное описание с примерами запросов — [Swagger UI](/api/docs) и
`docs/api.md` в репозитории.

## Что присылать в поддержку

1. **код обращения** со страницы отказа или из поля `requestId` ответа;
2. **что делали** — раздел, запись, кнопка;
3. **что увидели** — код и фразу целиком.

Снимок экрана полезен, но код обращения важнее: по нему в логе сервера лежит
полная запись о том, что случилось, — с местом в коде, которого пользователю не
показывают намеренно.
